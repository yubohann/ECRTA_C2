## 2. 研究问题与一句话主张（本轮锁定）

原始 C2 的执行层存在"对同一不可达目标重复 A* 失败"的失败链（open_plan_office/2 UAV 单轮 459~596 次，其中同一目标 238~463 次；cubicle_office/4 UAV 大量失败），拖长 makespan 与超时长尾。主张：

> 在 C2 固定三图、固定任务与固定求解器下，通过"确认阻塞 + 目标保持 + 失败证据反馈"在分配代价层、任务语义层与目标选择层同时减少不可执行目标的产生与重复重试，降低 makespan、失败率与尾部完成时间，不牺牲覆盖率、安全性与在线计算预算。

三方法分层：

- REACH（分配代价层）：A*/轨迹失败证据按 map_version+frontier+owner 登记，折算为 ACVRP 风险代价；
- SVR（任务语义层）：分配摘要 digest 复用，候选集不变时跳过重复 LKH 调用；
- STEER（目标选择层）：单 frontier 内失败视角轮换 + 目标保持时间 + 切换 margin + 连续 3 次确认，不做 peer 接管。

## 5. 每轮循环（标准动作，缺一不可）

### R0 固定格子（实验场景纪律）

只在已知高失败格子实验：open_plan_office/2 UAV、cubicle_office/4 UAV。禁止在低失败格子（如 open/3）跑正式对比。每轮先跑 B0 确认失败模式复现（触发门槛：单轮 A* 失败≥100 次）；不复现则换 seed 直到复现并记录 seed。

### R1 机制审计（改任何东西之前）

统计每方法事件：REACH 的 risk_adjusted_edges>0、SVR 的 reuse/stable_overlap>0、STEER 的 view_switch>0 且同目标连续失败链被中断。事件为 0 = 实现 bug 或未接进决策路径，先修代码，不许进入正式对比；修完用单实例 pilot 验证事件可触发、旧 peer/C3 路径事件为 0。

### R2 成对正式对比

B0/B1/REACH/SVR/STEER 同 seed 同实例，每方法≥5 次（目标 10-13），输出 makespan（未完成按 180s 截断计）、FINISH 率、A* 失败数、轨迹失败数、覆盖、碰撞告警、LKH 耗时；bootstrap 95% CI + Wilcoxon/置换检验；失败样本计入分母，JSONL 解析错误必须为 0。

### R3 逐层归因（先查实现，再查参数，最后才是方法无效）

1. 事件是否触发？→ 0 就是代码 bug，修；
2. 触发但无收益？→ 代价模型或触发条件不合理，只修该缺陷；
3. 有收益但不稳定？→ 参数灵敏度标定，不许只挑最好的 seed 报；
4. 全无收益？→ 如实记为负结果，进论文的负结果章节。

其中必然存在不是最佳的方法，这不意味着放弃：按 R3 定位到具体实现/参数问题后认真修改、认真优化，可以在所有第一以及非第一的方法上优化，反复思考后再跑一轮。

### R4 迭代优化循环（用户指定规则）

- 如果第一名不变：继续优化第一名，同时修/优化所有非第一名，再跑一轮；
- 如果第一名变了：对所有第一以及非第一的方法继续优化，再跑一轮；
- 循环往复，直到收敛或止损；
- 早停门槛：连续 2 轮第一名不变且对非第一名的两轮修复均未改变排名 → 收敛；若第一名相对 B1 无显著收益 → 主贡献收敛为"确认阻塞+目标保持+事件触发重选"，三方法写成机制消融。

### R5 数据卫生

所有 run 目录、日志、manifest、seed、参数、审计脚本全部保留；禁止删失败日志、挑选成功样本、伪造结果；每轮先提交再继续。

## 6. 网上对照（结果不理想时的强制动作）

在 R3 判定"无收益"后，禁止拍脑袋改参数。必须回到文献轮：找出与我们同层问题最接近的开源实现（优先 DAIB-Explorer 仓库代码），逐行读它的"确认-保持-切换-去重"逻辑，说明它为什么在它的场景成功、我们在什么层级/格子/条件差异下失败，写差距分析 md，再改代码。

## 8. 投稿判断（最终三条路）

- 主方法满足：相对 B1（或相对 B0，若 B1 在所有格子上不成立）在成对比较中显著改善，且覆盖率/碰撞/失败率不恶化、p95 分配耗时不增加 → 写论文，方法名=排名第一的方法，其余为机制消融；
- 未显著改善但有可靠机制证据 → 主张降级为"执行层失败链分析与抑制机制"；
- 全部未通过 → 交付严格负结果报告，不投稿或换题。
