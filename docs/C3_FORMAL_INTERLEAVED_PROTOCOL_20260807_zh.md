# C3 正式成对实验协议修订

## 1. 为什么修订

第一轮正式 batch 使用 method-major 顺序：先 5 个 B0，再 5 个 B1，最后 5 个 C3。

问题：

- 后运行的方法会受到系统状态、ROS 时间、GPU 温度等漂移影响；
- 不能把 C3 比 B1 慢直接归因于算法；
- n=5 且无官方随机种子时，不能作为论文结论。

## 2. 修订后的顺序

run_c3_formal_batch.sh 改为 instance-major 交错：

1. instance 1：B0, B1, C3
2. instance 2：B0, B1, C3
3. 依此类推

每个实例内部仍使用相同场景、UAV 数、时长和通信阈值。

## 3. 第一轮数据只作为过程记录

open_plan_office / 3 UAV / 5 m / 120 s / method-major 的 makespan 中位数：

- B0：74.83 s
- B1：75.83 s
- C3：89.80 s
- C3-B1 成对差：+8.60, +12.88, +54.24, +3.52, -6.27

结论：该批数据不用于投稿判断，只用于发现实验设计问题。

## 4. 后续门槛不变

- C3 相对 B1 成对 makespan 中位改善 >= 10%；
- 或未完成率改善 >= 20 个百分点；
- 覆盖率、碰撞、LKH 失败、在线时延不得退化；
- 失败样本全部进入分母。
