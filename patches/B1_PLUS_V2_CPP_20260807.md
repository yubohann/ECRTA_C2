# B1+ v2 代码修改说明

## 1. 目的

修复 B1+ v1 中 B1 与 B1+ 共用同一冷却路径的问题，并把“失败链”从累计失败改成连续失败后确认，避免把偶发失败误判为长期阻塞目标。

## 2. C++ 修改

文件：

- src/swarm_exploration/exploration_manager/include/exploration_manager/c2_exploration_manager.h
- src/swarm_exploration/exploration_manager/src/c2_exploration_manager.cpp

新增成员：

- bool prct_backoff_enabled_ = false;
- void registerPrctSuccess(const int frontier_id, const Vector3d& goal);

参数加载：

- nh.param("exploration/prct_backoff_enabled", prct_backoff_enabled_, false);
- ros::param::param("/prct_backoff_enabled", prct_backoff_enabled_, prct_backoff_enabled_);

冷却语义：

- B1：prct_backoff_enabled=false，prctFailureCooldownS() 始终返回固定 prct_cooldown_s。
- B1+：prct_backoff_enabled=true，按失败链指数退避，默认 5/5/5/10/20/30 s。
- 同一目标 A* 成功后调用 registerPrctSuccess()，清零该目标和冷却键的连续失败计数。
- 遥测新增 prct_failure_chain_reset 事件。

## 3. launch 修改

三张官方场景 launch 均新增：

- arg prct_backoff_enabled，默认 false
- param prct_backoff_enabled，type=bool

## 4. 脚本修改

- run_scene_pilot.sh：新增第 33 个参数，写入 manifest、launch 参数和 prct_check.tsv。
- run_b1plus_batch.sh：B1 固定冷却，B1+ 自适应冷却，方法不再混同。
- audit_peer_handoff_active.py：新增 prct_failure_chain_reset_count。

## 5. 验证记录

- 编译：catkin_make -j2 成功，exploration_node 已重新链接。
- B1 pilot：prct_backoff_enabled=false，prct_check.tsv 全 match。
- B1+ pilot：prct_backoff_enabled=true，6 次失败、6 次 register、5 次 skip，遥测包含 backoff_enabled=1。
- 成功重置版本：3 次连续失败后进入冷却，未发现运行时错误。
- 2 UAV 压力 batch：B0/B1/B1+ 均 FINISH，但该实例三种方法均无 A* 失败，因此只作为参数和运行审计，不作为收益证据。

## 6. 边界

当前没有足够样本证明 B1+ 优于 B1。下一步继续跑失败率更高或时长更长的成对实例，任何收益结论都必须等统计样本完成。
